# 合約類型全覽：Fixed Price／Cost Reimbursable／T&M

> [[Projects/PMP/知識庫/_索引|← 知識庫索引]] ｜ `Governance 績效領域` › `Planning` › `Plan Sourcing Strategy`

> [!tip] 一句話核心
> **誰承擔風險，誰就沒有省錢的動力。** 三大合約家族排在一條光譜上：**Fixed Price（賣方全扛風險）→ Time & Material（風險對半）→ Cost Reimbursable（買方全扛風險）**。範疇越清楚，越適合把風險推給賣方（Fixed Price）；範疇越模糊，越只能買方自己扛（Cost Reimbursable）。

---

## 風險光譜：一張表看完三大家族

|                 | **Fixed Price 固定總價**   | **Time & Material 工時material** | **Cost Reimbursable 成本補償**   |
| --------------- | ---------------------- | ------------------------------ | ---------------------------- |
| **風險在誰身上**      | **賣方**                 | 買賣雙方**對半分**                    | **買方**                       |
| **賣方控制成本的動力**   | **最高**（超支自己吸收，省下的就是利潤） | 中等                             | **最低**（成本全額報銷，沒有省錢誘因）        |
| **範疇要多明確才能用**   | **範疇清楚、明確**，能一開始就談好總價  | 範疇**部分明確**，工作量不確定但單位費率固定       | **範疇不確定、難以界定**（研發、新技術、探索性工作） |
| **合約簽訂時能不能報總價** | 能                      | 只能報**單位費率**（時薪＋材料費），總額事後才知道    | 不能，只能先估、邊做邊報帳                |
| **買方管理負擔**      | 低（簽完等交貨）               | **高**（要持續追蹤工時與材料花費）            | 高（要審核每一筆報銷成本）                |

> 🔑 記憶口訣：**範疇明確度 ↑ → 風險推給賣方 ↑ → 選 Fixed Price。範疇明確度 ↓ → 風險留在買方 ↓ → 選 Cost Reimbursable。** T&M 是中間的過渡型，常用在小額、短期、範疇會邊做邊調整的工作（如顧問時數）。

---

## ① Fixed Price 家族（賣方扛風險）

| 子類型        | 全名                                                    | 怎麼運作                                                                                          |
| ---------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| **FFP**    | Firm Fixed Price（確定總價）                                | 一口價，不管賣方實際花多少成本，買方就付這個數字。**最單純、賣方風險最大**                                                       |
| **FPIF**   | Fixed Price Incentive Fee（總價加激勵費）                     | 有一個目標成本＋目標利潤，若賣方**實際成本低於目標**，雙方依約定比例**分享省下的錢**；超支則依比例分攤（但買方分攤有上限，超過封頂 Price Ceiling 後全部由賣方吸收） |
| **FP-EPA** | Fixed Price with Economic Price Adjustment（總價加經濟價格調整） | 總價固定，但允許因**通膨、匯率、原物料價格**等外部經濟因素做**條款約定內的價格調整**。常用於**長期合約**，避免賣方因通膨被綁死                         |

---

## ② Cost Reimbursable 家族（買方扛風險）

| 子類型      | 全名                              | 怎麼運作                                                     |
| -------- | ------------------------------- | -------------------------------------------------------- |
| **CPFF** | Cost Plus Fixed Fee（成本加固定費）     | 報銷實際成本＋**一筆固定金額**的利潤，這筆費用**不隨成本變動而變動**（成本超支不會讓利潤跟著變多）    |
| **CPIF** | Cost Plus Incentive Fee（成本加激勵費） | 報銷實際成本＋一筆**依績效表現浮動**的利潤（達成或超越某個目標如提前完工、控制成本，利潤會增加）       |
| **CPAF** | Cost Plus Award Fee（成本加獎勵費）     | 報銷實際成本＋一筆**由買方主觀評定**、依整體滿意度發放的獎勵金（金額由買方**單方面裁量**，賣方無法申訴） |

> 💡 CPIF vs CPAF 的差別：**CPIF 的獎勵公式寫在合約裡（客觀、可預期）；CPAF 的獎勵金額由買方主觀評分決定（不可預期、賣方沒有異議權）。**

## ③ Time and Material（T&M，工料合約）

| 面向       | 內容                                                                                         |
| -------- | ------------------------------------------------------------------------------------------ |
| **怎麼付錢** | 按**實際投入的工時 × 約定時薪** ＋ **實際材料成本**計價，事先只談**費率**，不談總額                                         |
| **風險**   | 介於 Fixed Price 與 Cost Reimbursable 之間，**買賣雙方共同承擔**——賣方的時薪費率固定（有壓力控制工時效率），但買方要承擔工時可能超出預期的風險 |
| **適用情境** | **金額小、期程短、範疇無法一開始就寫清楚**的工作（如技術顧問、小型維修、按需支援）                                                |
| **管理重點** | 買方需要**設定工時或金額上限（Not-to-Exceed）**，否則賣方沒有動力控制工時，總金額可能失控                                      |

## 🎯 判準：題目在描述什麼特徵，對應哪個家族

| 題目描述                           | 對應合約類型                           |
| ------------------------------ | -------------------------------- |
| 範疇**清楚明確**，能簽一口價               | **Fixed Price（FFP）**             |
| 一口價，但**允許因通膨等外部經濟因素調價**        | **FP-EPA**                       |
| 一口價，但**成本省下來雙方分紅、超支雙方分攤（有封頂）** | **FPIF**                         |
| **報銷實際成本＋固定利潤**，利潤不隨績效變        | **CPFF**                         |
| **報銷實際成本＋利潤依績效公式浮動**           | **CPIF**                         |
| **報銷實際成本＋利潤由買方主觀評分決定**         | **CPAF**                         |
| **按時薪＋材料費計價**，事先不知道總額，金額小、期程短  | **Time and Material（T&M）**       |
| **範疇不確定、難以界定**，泛稱這整類合約         | **Cost Reimbursable（泛稱，不特定子類型）** |

## E042 · 關於 Cost Reimbursable 合約，哪一項不正確（原始錯題）

| 敘述                   | 對不對     | 為什麼                                                        |
| -------------------- | ------- | ---------------------------------------------------------- |
| 買方報銷賣方實際成本＋一筆費用      | ✅ 對     | 這是 Cost Reimbursable 的**定義本身**                             |
| 買方承擔合約中大部分的成本風險      | ✅ 對     | 成本花多少都算買方的，風險自然在買方                                         |
| 合約適用於範疇不確定、難以界定的情況   | ✅ 對     | 範疇模糊才需要這種「先做再報帳」的彈性合約                                      |
| **賣方有最大動力控制成本、提高效率** | ❌ **錯** | 賣方成本能全額報銷，**沒有財務誘因**去省錢——這句話其實是在描述 **Fixed Price** 合約的賣方心態 |

> 💡 陷阱模式：把「Fixed Price 合約才有的敘述」放進 Cost Reimbursable 的選項裡，測你是否記得**兩種合約的風險方向剛好相反**。看到「賣方有動力／誘因控制成本、提高效率」這句話，先確認題目問的是哪一種合約——這句話**只在 Fixed Price 底下成立**。

## CPIF／FPIF 計算公式：Share Ratio 怎麼算

> [!tip] 一句話核心
> **先算「超支或省下多少」，再用 Share Ratio 分那個差額，最後把分完的錢加回／扣回目標費用。** 公式永遠是同一套邏輯，CPIF 跟 FPIF 只是套用在不同合約家族上。

### 標準四步驟

1. **算成本差額**：`實際成本 − 目標成本` → 正數＝超支，負數＝省下
2. **用 Share Ratio 分攤差額**：Share Ratio 寫成 `買方% / 賣方%`（如 70/30），**差額 × 賣方%** 就是賣方要分攤（超支時）或分到（省下時）的部分
3. **算最終費用（Final Fee）**：
   - 超支時：`目標費用 − 賣方分攤的超支金額`
   - 省下時：`目標費用 + 賣方分到的節省金額`
4. **算最終價格（Final Price）**：`實際成本 + 最終費用`

> ⚠️ 常見誤區：**成本超支時，賣方的費用（Fee）會被扣錢**，不是賣方按比例多拿——超支對賣方是**懲罰**，不是**多賺**。方向搞反是最容易錯的地方。

### 套用範例（E043 原始錯題）

| 步驟 | 算式 | 結果 |
|---|---|---|
| 條件 | Target Cost \$150,000／Target Fee \$15,000／Actual Cost \$163,000／Share Ratio 70/30（買方/賣方） | — |
| ① 成本差額 | \$163,000 − \$150,000 | **超支 \$13,000** |
| ② 賣方分攤超支 | \$13,000 × 30%（賣方比例） | **\$3,900** |
| ③ 最終費用 Final Fee | \$15,000 − \$3,900 | **\$11,100** |
| ④ 最終價格 Final Price | \$163,000（實際成本）＋ \$11,100（最終費用） | **\$174,100** |

### 為什麼其他答案錯

| 錯誤答案 | 錯在哪 |
|---|---|
| **\$15,000 and \$178,000**（你選的） | 直接把 Target Fee 當 Final Fee，**完全沒扣超支分攤**——等於認為超支對賣方沒有任何懲罰 |
| \$18,100 and \$181,100 | 把差額方向算反，變成**費用因超支而增加**（\$15,000+\$3,100），邏輯上超支不該讓賣方多拿錢 |
| \$13,000 and \$176,000 | 把 Share Ratio 用錯邊，拿 70%（買方比例）去扣費用，而不是 30%（賣方比例） |

> 💡 陷阱模式：四個選項通常對應「正確算法」「忘記扣超支」「方向算反（超支反而加錢）」「Share Ratio 用錯邊」這四種典型錯法。算完先問自己：**超支應該讓賣方的錢變少，還是變多？**——變少才對。

## 規格類型：Performance vs Design——技術風險轉嫁給誰

> [!tip] 一句話核心
> 這是**合約付款方式**之外，另一個獨立的採購維度：**買方規定「要什麼結果」還是「怎麼做」，決定技術風險落在賣方還是買方。** 規定結果（Performance Spec）→ 賣方自己想辦法達成，做不到算賣方的；規定做法（Design Spec）→ 買方等於幫賣方做了決定，做法錯了算買方的。

| 規格類型                                                                    | 買方規定什麼                             | 技術風險在誰身上                                    | 賣方彈性                  |
| ----------------------------------------------------------------------- | ---------------------------------- | ------------------------------------------- | --------------------- |
| **Performance Specification**<br>性能規格（又稱 Functional Specification 功能規格） | 只規定**要達成的結果**（產出、產能、效率、可靠度），不規定怎麼做 | **賣方**——沒達到性能要求，賣方要自費重新設計、返工、更換             | **高**——賣方可自由選擇設計與實作方法 |
| **Design Specification**<br>設計規格                                        | 規定**具體要怎麼做**（材料、方法、規格細節）           | **買方**——如果賣方照買方指定的方法做，結果卻不如預期，責任在**下指令的買方** | 低——賣方只是照做，沒有決策空間      |

> 🔑 判準口訣：**規定「What」→ 風險給賣方；規定「How」→ 風險留買方。** 因為規定 How 等於買方替賣方做了技術決策，賣方只是執行者，執行者不該為別人的決策錯誤負責。

### 為什麼答案是 Seller，不是其他角色

| 錯誤選項 | 為什麼錯 |
|---|---|
| **Project sponsor**（你選的） | Sponsor 提供資金與策略方向，**不涉及賣方技術方案是否達標**這種執行層級的責任 |
| Project manager | PM 協調、監督合約履行，但**技術風險屬於實際負責交付的一方**，不是監督者 |
| Customer（買方） | 買方只負責**定義**要什麼性能目標，**如何達成**的風險已經**轉移給賣方**——買方保留的只是「目標定得對不對」的風險，不是「做不做得到」的風險 |

## 補充：買方技術不夠懂，如何降低 Design Spec 的風險

> [!tip] 一句話核心
> Design Spec 對買方最大的痛點不是「多做白工」，而是**買方不見得是真正的技術專家，卻要為規格對不對負全責**。實務上有幾種機制可以在簽約前後，把賣方的技術知識「借」回來，降低這個落差。

| 機制 | 怎麼做 | 解決什麼問題 |
|---|---|---|
| **Bidder Conference**<br>投標人會議／廠商說明會 | **簽約前**召集所有潛在賣方開會說明規格，**讓賣方當場提問、指出規格裡的技術疑慮**——PMBOK 官方工具 | 在花錢之前，用一群專家的眼睛幫忙檢查規格有沒有問題 |
| **混合規格**：關鍵處用 Design，其餘留給賣方判斷 | 只規定自己真的懂、必須固定的部分（安全規範、介面規格），其餘技術細節改用 Performance Spec 邏輯 | 買方只對自己有把握的部分負責，其餘風險自然轉移給賣方 |
| **Value Engineering 條款**（價值工程） | 合約載明：賣方發現規格有更好做法可以提案變更，經核准後省下的成本雙方分享 | 給賣方「主動糾正買方規格盲點」的誘因，而不是照著錯的規格悶頭做 |
| **獨立 SME 審查** | 招標前先請**不參與投標的第三方顧問**審查規格 | 避免只依賴「即將靠這筆案子賺錢」的賣方意見（賣方建議可能有利益考量） |
| **Spearin Doctrine**（隱含保證原則，英美契約法概念） | 買方提供設計規格＝隱含保證這個規格可行；賣方照做做不出來，責任回買方；但賣方**施工前明知規格有問題卻不提出警告**，也要負一部分責任 | 法律層面對「買方不夠懂技術」的一種平衡機制，避免責任完全單方壓在買方 |

> 🔑 最實用的組合：先辦 **Bidder Conference** 收集賣方意見修正規格 → 規格裡加 **Value Engineering** 條款留活路 → 只在買方真的有把握的地方用 Design Spec，其餘交給賣方（回到 Performance Spec 的風險轉移邏輯）。
