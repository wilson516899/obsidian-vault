## ⚠️ 先讀：這份診斷的資料限制

這份分析**只根據 37 則「答錯」的題目**產生。它看不到：

- 你的整體正確率
- **沒把握但蒙對的題**（這是最大的盲點，見下方第五節）
- 你真正掌握得好的領域

> 🔑 因此這份文件的結論**天然偏向「你哪裡不行」**。不要拿它當能力評估，它是**方向指引**。

## 一、核心診斷：不缺知識，缺辨析精度

逐題檢查**你選錯的那個選項**，結果：

| 類別 | 題數 | 佔比 |
|---|---|---|
| 你選的是**真實存在、完全正確**的 PM 概念，只是不適用該題 | 34 | **89%** |
| 真正「沒聽過」的知識缺口（E013、E017、E030、E035） | 4 | 11% |
| 純執行失誤（E014 沒算就選、E028 路徑沒窮舉、E029 方向看反） | 3 | 8% |

> [!tip] 結論
> **繼續「讀更多新知識」的邊際效益很低。**
> 失分點在「兩個都對的東西之間，挑出題目真正要的那一個」。
> 辨析能力**無法靠讀 PMBOK 練出來**——讀十遍還是會在 Theory Y / Theory Z 之間選錯，因為問題不在「懂不懂」，在「都懂的時候怎麼選」。

## 二、五個失分模式（含錯題編號，可回溯）

> ⚠️ 模式之間有重疊，以下標的是**主要**歸類，不是互斥分類。

### 模式 A｜層級／顆粒度抓錯 ★最大宗（9 題）

選項全在同一個主題家族，但**分屬不同抽象層級**，抓錯了層。

| 錯題 | 你選的層 | 該選的層 |
|---|---|---|
| E019 | Program（執行協調層） | Portfolio（投資決策層） |
| E017 | Manage QA（稽核／規劃層） | Validate Scope（逐件檢驗層） |
| E025 | 以為「掌管資源」屬執行層 | 啟動層（章程簽署即授權） |
| E023 | 排程技術（工具層） | 心態價值觀（最上層） |
| E035 | Theory Y（個人態度層） | Theory Z（組織制度層） |
| E020 | HR（行政層） | Functional Manager（組織長期人才層） |
| E026 / E030 | CPM（路徑分析層） | PERT／PDM（單一活動層） |
| E032 | WBS（交付物軸） | OBS（組織軸） |

> 🔑 **對策**：看到選項全是同家族名詞時，先問「題目在問**哪一層**的事」，再選。

---

### 模式 B｜系統性偏向「更積極、更全面」的選項（5 題）

E002（開團隊會議講期望）、E004（選「主動關係人參與」）、E007（開策略審查會議）、E009（頻繁開關係人會議）、E010（對全部 47 種做 RCA）

這些都是「**一個負責任的 PM 聽起來會做的事**」。但 PMP 問的是「**流程上此刻該做的那一步**」。

> 🔑 這跟分析型人格「先蒐集更多、做更全面的動作」的傾向一致，會系統性把你推向「開會／再評估／全面分析」類選項。
> **對策**：看到選項含「召開會議」「全面評估」「與所有關係人討論」，**先假設它是干擾項**，要求自己證明它不是。

---

### 模式 C｜干擾項全是真的（7 題）

E016、E018、E021、E027、E031、E033、E037

特徵：**四個選項都是真實存在的工具／原則／實踐**，不是三假一真。

> 🔑 這類題考的不是「知不知道這個名詞」，是「**說不說得出它的目的／對象／時機**」。
> **對策**：認得名詞不夠，要能一句話說出「它解決**誰**的**什麼**問題」。

---

### 模式 D｜時態／順序錯置（4 題）

| 錯題 | 錯誤 |
|---|---|
| E015 | 問「未來要多有效率」（TCPI），答成「目前多好」（CPI）／「總共多少錢」（EAC） |
| E012 | 成本基準**建立後**才導出資金需求，順序顛倒 |
| E010 | 應是 Pareto 找少數 → 再對那幾個做 RCA |
| E033 | Sprint Review（先，對外）→ Retrospective（後，對內） |

> 🔑 **對策**：方向對不代表答案對。先確認題目問的是**過去／現在／未來**，以及**這一步之前該做完什麼**。

---

### 模式 E｜方法論混用（5 題）

E003、E006、E009、E024、E034——把預測型思維套進敏捷情境（或反之）。

> 🔑 **對策**：主計畫裡「**我現在在哪個世界？**（預測／敏捷／混合）」這個提問要**在讀選項之前**先問完。
> 訊號詞：敏捷情境出現 `change request`／`scope baseline`／`CCB`／`formal approval`／`Project Manager 頭銜` → 幾乎都是干擾項。

---

### 次要｜視野太窄（2 題）

E008（只看時程單一面向）、E036（EVM 只選一份文件）——與模式 B 方向相反，提醒：**不是「越保守越對」，是「範圍要剛好對應題目問的」**。

## 三、複習大綱：照「辨析軸」走，不要照 7 大領域走

因為錯誤不是分散在領域裡，是集中在近義概念上。

```
第一軸：辨析（約 65% 的錯在這）
├─ A1 層級辨析
│   ├─ Portfolio / Program / Project / Operations
│   ├─ 啟動 vs 規劃的產出邊界（高層級授權 vs 詳細拆解）
│   ├─ Manage QA vs Validate Scope（PMBOK 8 品質流程搬家）
│   ├─ PM vs Functional Manager vs Sponsor vs HR
│   └─ Agile 心態 → 框架(Scrum/XP) → 實踐(CI/TDD/User Story)
├─ A2 工具辨析（同類工具選哪個）
│   ├─ 結構圖組：WBS / OBS / RBS / RAM
│   ├─ 品質工具：Pareto / RCA / 管制圖 / 散佈圖 / 直方圖 / 因果圖
│   ├─ 時程技術：PERT / CPM / PDM / ADM / Lead-Lag
│   └─ EVM 指標：CPI / SPI / TCPI / EAC / ETC（含「時態」判準）
└─ A3 方法論對應（預測型 ↔ 敏捷 的機制對照）
     範疇基準↔Backlog｜變更請求↔重排｜CCB↔PO｜PM↔SM/Coach

第二軸：順序鏈（背「鏈」不背單點）
├─ 成本鏈：估算→彙總→+應急→成本基準→+管理準備→專案預算→資金需求
├─ 品質鏈：Pareto 找少數 → 再對那幾個做 RCA
├─ 敏捷鏈：Planning → Standup → Review → Retrospective
└─ 衝突鏈：私下一對一 → 團隊公開 → 升級

第三軸：計算（唯一「練了就穩」的區塊）
└─ EVM 四層公式 / CPM 窮舉路徑 / PERT 加權
     已錯 5 題：E014、E015、E026、E028、E036 ← 投報率最高
```

## 五、刷題補觀念：方法有效，但有一個漏洞

### ✅ 方法判定：可行，而且對你特別合適

PMP 一半是情境題，考的是「四個都合理時選哪個」，不是回憶名詞。
而你的錯題剖面（89% 辨析失敗 / 11% 知識缺口）正好證明：**判別力只能靠大量被迫做判別的樣本訓練**。方向不用改。

### ⚠️ 漏洞：蒙對的題是隱形的

只記錄「選錯」的題，會漏掉**在兩個選項間猶豫、最後蒙對**的那批。
它們的底層弱點與答錯完全相同，但不會進錯題本——**在考場上會變成真正的錯題**（沒有即時解答、沒有時間慢慢排除）。

> 📌 主計畫裡「**猜對的題也要記**」這條規則已經寫了，但實際執行時沒有落實。這是目前最該補的一件事。

### 補法：答題時標信心值（多花 2 秒）

| | 答對 | 答錯 |
|---|---|---|
| **有把握** | ✅ 真掌握，跳過 | 🔴 **最危險**——觀念是反的，優先處理 |
| **沒把握** | 🟡 **隱性錯題，要進錯題本** | ✅ 已捕捉 |

> **右上（有把握但錯）和左下（沒把握但對）才是真正該投資的地方。**
> 目前只捕捉到右下那格。

## 七、下一步（按投報率排序）

1. **改變答題方式**（零成本，立刻可做）
   每題**先寫下「我為什麼排除另外三個」**再選答案。直接打核心弱點（辨析精度），並逼你從「哪個看起來對」切換到「哪個不對、為什麼」。
   → 這也正是主計畫裡「出考場的質化判準」。

2. **標信心值，把「沒把握但蒙對」的題也交出來**
   這批題的診斷價值高於再多給十題錯題。

3. **主動測盲區**
   去做 **Risk / Stakeholders / Closing** 的專項題組。目標是**把錯誤逼出來**，不是刷高正確率。

4. **計算題集中練 20 題**
   EVM + CPM + PERT。唯一能靠純練習穩定拿分的區塊，且已錯 5 題。
