## Obsidian + AI 第二大腦架構

來源：[YouTube 教學影片](https://www.youtube.com/watch?v=RZEb6FLZSHE)

### Vault 設計核心原則：按需讀取

- Claude **不**掃整個 Vault，只讀當下需要的那一層
- 讀取順序：`CLAUDE.md` → 按需進入子資料夾
- 用最近 3 天的 Daily Notes 作為短期記憶，大幅節省 Token

### 每日工作流

1. 開新 Claude Code session
2. Claude 自動讀 `CLAUDE.md`
3. 讀最近幾天 Daily Notes 取得記憶
4. 開始工作

### 快速捕捉

- iPhone Action Button → 一鍵語音輸入 → 自動存入 Inbox
- 書籍 Highlight → 一鍵存入 Reading 資料夾，AI 整理成筆記

### 核心觀念

- 第二大腦的價值在於「讓資訊可以輕鬆流動」
- 存東西要夠方便，才能持續使用
- AI 讀你的筆記 → 了解你 → 變成你的專屬 AI

## RAG 檢索策略

針對表格、圖片、網址三種難題的可落地做法。

### 三種難題的處理方式

**表格讀不到 → 轉成可檢索的文字結構**
- 工具：`pdfplumber`（PDF）、`pandas.read_excel`（Excel）、`camelot`/`tabula`（掃描 PDF）
- 轉成 Markdown 表格或 CSV，並加上行內摘要
- 建立欄位字典（schema），支援同義詞檢索
- 保留單元格座標與來源頁碼，便於命中後擴展上下文

**圖片讀不到 → OCR + 圖像描述**
- OCR：`tesseract`（快）、`paddleocr`（準）
- 為圖片生成 1–3 句說明（圖表類尤其有效）
- 多模態向量庫（CLIP、SigLIP）補圖向量，命中時融合排序

**網址讀不到 → 抓取＋正文抽取＋快照**
- 工具：`Playwright`/`puppeteer`（動態頁）、`trafilatura`/`readability`（正文抽取）
- 保存「純文本正文 + 主要圖片 + 原始 HTML」三份
- 保存內容哈希與抓取時間，防止來源失效

### 避免「切碎後相關性下降」的檢索層設計

| 策略 | 說明 |
|------|------|
| 語義切塊 | 以段落/標題為邊界，512–1000 tokens，重疊 10–20% |
| 父子檢索 | 命中子塊 → 回溯父塊一起送進模型 |
| 鄰接擴展 | 命中第 i 塊時，帶上 i-1、i+1 |
| 混合檢索 | 向量檢索 + BM25 關鍵詞同時跑，再 Rerank |
| 元資料過濾 | 先用 metadata 限定範圍，再做語義檢索 |

### 查詢路由（Query Routing）

- **表格型**（含數字/欄位詞）→ 優先檢索 table 類文檔
- **圖片/圖表型** → 搜 image captions，再融合多模態排序
- **網址/即時** → 先查 URL 快照庫，失效再觸發更新
- **一般長文** → 混合檢索 + 父子檢索

### 推薦元件

| 用途 | 工具選項 |
|------|---------|
| 解析 | `pdfplumber`、`pandas`、`camelot`、`trafilatura`、`playwright` |
| OCR | `tesseract`、`paddleocr` |
| 嵌入 | OpenAI `text-embedding-3-large`、`bge-m3`、`gte-large` |
| 向量庫 | `Milvus`、`Weaviate`、`Qdrant` |
| Rerank | `bge-reranker`、`colbert` |
| 多模態 | CLIP、SigLIP |
