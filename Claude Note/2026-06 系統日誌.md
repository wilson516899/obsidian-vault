## ✅ 新增

### git-sync（cron 23:05）
**做了什麼：**
- 建立 `Skills/git-sync/git_sync.sh`
- 每天 23:05 自動 `git add -A → commit → push origin main`
- log 輸出至 `/tmp/git-sync.log`

**推論：**
Vault 有多支腳本每天修改檔案，但沒有自動備份。每天手動 push 容易忘記，造成 GitHub 長期沒有更新。git-sync 讓備份變成零成本的背景任務。

---

## 🐛 修復（6/7）

### quest.py NameError（啟動即崩潰）
**修了什麼：**
- `AGENDA_PATH` 第 17 行用了 `YESTERDAY`，但 `YESTERDAY` 到第 21 行才定義
- Python 從上到下執行，每次 cron 07:55 都是 NameError，積分從未結算

**推論：**
重構 Global 常數時調整了 AGENDA_PATH 位置但沒同步移動 `TODAY`/`YESTERDAY` 定義。沒有 log 讓人察覺，bug 靜默存在。修法：把 `TODAY`/`YESTERDAY` 移到 AGENDA_PATH 之前。

---

### extract_daily_note_summary() 抓到簡報噪音
**修了什麼：**
- 正則 `(?=\n## |\n---\n##|\Z)` 無法在 `## 每日簡報` 前停止（實際格式是 `\n---\n\n##`，雙換行）
- match 跑到 `## 隨手記` 才停，把整個每日簡報都帶進 notify.py 的上下文
- 修為 `(?=\n---|\n## |\Z)`，遇到任何 `---` 分隔線即停

**推論：**
這讓 notify.py 讀過去 7 天時把舊新聞帶回來，形成回音並浪費 token。根本原因是模板有額外換行，但正則沒有對應。

---

### 主頁.md 今日連結自動更新
**修了什麼：**
- `notify.py` 加入 `update_homepage()`，每天 08:00 自動正則替換主頁的今日 Daily Note 連結日期
- 修正主頁 Skills 連結（`Obsidian/Skills/instructions` → `Skills/instructions 2`）

**推論：**
主頁「今日」連結若硬編碼就每天過時，但手動維護容易忘。讓 notify.py 順帶更新是零成本解法。

## 🔄 調整（6/8）

### 寫作計分機制：每完成一本各給分
**改了什麼：**
- `quest.py`：從 `WEEKLY_TASKS` 移除「寫作」，不再每週去重
- `notify.py`：`weekly_checkbox` keywords 移除「寫作」「書摘」，寫作 checkbox 改為直接輸出（不做去重判斷）
- 寫作仍放在本週任務區塊（維持週任務的框架），但每次勾選都獨立計 +25

**推論：**
原設計「每週只計一次寫作」的假設是用戶每週只寫一本，但實際上用戶有時想一次填多本書摘。改為「每寫一本各給一次分」讓積分反映實際付出，同時保留週任務的框架（不改成每日固定任務），避免「今天沒寫就有缺口」的心理壓力。

---

### `instructions 2.md` 改名為 `skills-index.md`
**改了什麼：**
- `Skills/instructions 2.md` → `Skills/skills-index.md`

**推論：**
Obsidian 在多個資料夾都有 `instructions.md` 時，會自動加 " 2" 後綴避免歧義。用唯一名稱 `skills-index.md` 根本解決衝突，不再需要繞過 Obsidian 的命名機制。

### book_fill.py：sync_status 補同步 body blockquote
**改了什麼：**
- `sync_status()` 現在同時更新 frontmatter `狀態: 待確認 → 已讀` 與 body `> 狀態：待確認 → > 狀態：已讀`

**推論：**
書籍模板有兩處狀態欄位（YAML frontmatter + body 引用區塊），原本只改 frontmatter，導致顯示不一致（上面改了、下面沒改）。

---

### book_fill.py：多本備選書推薦 + cron 提前至 07:58
**改了什麼：**
- `main()` 改為隨機挑 3 本：1 主推 + 2 備選，寫入 `本週任務.md`
- `write_weekly_task()` 加入 `extra_books` 參數，輸出備選書單區塊
- book_fill.py cron：`5 8 * * 1`（08:05）→ `58 7 * * 1`（07:58），確保在 notify.py 08:00 之前執行

**推論：**
單一推薦 + 多書計分機制不夠用，需要讓用戶在每週 Daily Note 就能看到備選書單。cron 調整是因為原本 08:05 比 notify.py（08:00）晚，導致週一 Daily Note 抓不到新的本週任務。
