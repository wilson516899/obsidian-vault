# 📐 品飲記錄格式規範

> 本文件定義 `調酒學習/品飲記錄/` 底下每一篇筆記的標準格式。
> 新增品飲記錄時，Claude 應依此規範建檔，不需每次重新詢問格式。

---

## 檔名規則

- **一律用英文命名**（看起來專業、也方便未來英文資料串接），檔名即該杯調酒的正式英文名
  - 例：`Negroni.md`、`Gimlet.md`、`Berlin Stationmaster.md`
- 有正式英文學名的調酒（經典酒譜）→ 用該學名
- 無正式學名的自創/酒吧特調 → 取一個像樣的英文名（可音譯或意譯），中文原名放在標題與 tags 裡保留
  - 例：小花自創調酒 → `Xiaohua's Original.md`；柏林站長 → `Berlin Stationmaster.md`

---

## Frontmatter 欄位

```yaml
---
基酒: <六大基酒之一，或多基酒用「+」連接>
結構: <Sparkling | Sour | Spirit-Forward | 其他>
分類: <18杯 | 同格變體 | 框架外>
品飲日期: <YYYY/MM/DD，只知道月份可寫 YYYY/MM>
評分:
  甜: <0-5>
  酸: <0-5>
  苦: <0-5>
  酒感: <0-5>
  酒體: <0-5>
  偏好: <0-5，可有 0.5 級距；校準基準飲品(Negroni)寫 "校準基準">
香氣: [<標籤1>, <標籤2>]
tags: [調酒, 品飲記錄, <基酒>, <分類>]
---
```

### `香氣` 欄位：為什麼需要它

五維評分（甜酸苦酒感酒體）記的是**強度**，但決定偏好的是**香氣身份**。最清楚的證據：

| 酒 | 甜 | 酸 | 苦 | 酒感 | 酒體 | 偏好 |
|---|---|---|---|---|---|---|
| Sangria | 3 | 0 | 0 | 1 | 1 | **4** |
| Cuba Libre | 3 | 0 | 0 | 1 | 0 | **2** |

五個數字幾乎相同、分數差 2 分，差別只在 Sangria 有香料味、Cuba Libre 是可樂。沒有 `香氣` 欄位，這個最關鍵的變數就只能躺在自由文字裡，無法查詢或統計。

### 香氣標籤詞彙表（封閉清單，不要自創新詞）

| 標籤 | 定義 |
|---|---|
| `苦味系` | 金巴利、苦精、Amaro 等帶來的直接苦味 |
| `草本藥草` | 藥草、根莖、香艾酒的草本調 |
| `薄荷` | 薄荷甜酒、涼感 |
| `香料` | 肉桂／丁香／八角等溫暖香料 |
| `煙燻` | 泥煤威士忌、Mezcal 的煙燻感 |
| `發酵酒系` | 紹興、雪莉、紅酒等釀造酒帶來的風味 |
| `基酒本味` | **風味主體來自烈酒本身**，沒有被外加材料蓋過 |
| `花香` | 薰衣草、接骨木花等花系利口酒 |
| `柑橘皮` | 橙酒 Triple Sec / Cointreau 的橙皮調 |
| `果汁酸` | 檸檬／萊姆等柑橘汁為主軸的酸 |
| `果香` | 莓果、熱帶水果、果汁的甜香 |
| `堅果` | 杏仁（Orgeat）、榛果、雪莉的堅果感 |
| `薑` | 薑汁啤酒、薑糖漿 |
| `奶蛋` | 蛋白、鮮奶油帶來的質地與乳香 |
| `無明顯特徵` | **風味只有甜或酸，沒有記憶點**（如 Cuba Libre「有甜味的可樂」） |

**標記原則**：只根據使用者「個人筆記」裡**實際寫過的描述**標記，不能依酒譜推測。使用者沒提到的香氣就不標——`香氣` 記的是「他喝到什麼」，不是「這杯理論上有什麼」。

新增標籤前請先確認現有 15 個真的都不適用，隨意擴充詞彙表會讓統計失去意義。

**`結構` 與 `分類` 是兩件事，不要混用**（這是 2026/09/20 修正的舊錯誤：早期把 `Free Exploration` 這個分類值填進 `結構` 欄，導致 12 杯的結構資料遺失，無法做「列出所有 Spirit-Forward 比分數」這類查詢）：

- **`結構`** = 這杯酒**本身的味道骨架**，永遠填三結構之一，與它在系統裡的身份無關
  - `Sparkling` 氣泡型／`Sour` 酸甜型／`Spirit-Forward` 烈酒型
  - 真的不屬於任何一種才填 `其他`（目前只有 Sangria 紅酒潘趣、Screwdriver 兩料果汁長飲）
  - 例：Old Fashioned 就算不在 18杯清單裡，`結構` 仍然是 `Spirit-Forward`
- **`分類`** = 這杯酒在 18杯系統裡的**身份**（判斷規則見下方「歸類規則」）
  - `18杯`：填滿 18 格其中一格的代表款
  - `同格變體`：該格已被填滿，這杯是同格子的另一種配方 → 需同步更新深度層
  - `框架外`：跨基酒混調、或框架外的經典家族
- **評分基準**：以 Negroni 為感官錨點（甜2 / 酸1 / 苦4 / 酒感4 / 酒體4），其他調酒的分數都相對這杯定位，不是絕對值

## 內文結構（依序）

```markdown
# <英文名>（<中文名>）

> （選填）標記校準基準飲品，或標記 18杯清單歸屬：「18杯清單：<基酒> × <結構>」

## 酒譜

| 材料 | 份量 |
|------|------|
| ... | ... |

- **手法**：Shake / Stir / Build（搖盪／攪拌／直調）
- **杯型**：Coupe / 岩杯 / Highball / 馬丁尼杯 等
- **裝飾**：（選填）

## 感官記錄

\`\`\`
甜  ●●○○○  2
酸  ●○○○○  1
苦  ●●●●○  4
酒感 ●●●●○  4
酒體 ●●●●○  4
偏好 ●●●○○  3
\`\`\`

## 個人筆記

（第一人稱的品飲心得，保留原始口語表達，不用幫使用者美化或修飾成品酒師術語）

## 延伸探索

- **<推薦調酒>**（來源脈絡，例如「18杯清單 龍舌蘭 × Spirit-Forward，尚未完成」）— 推薦理由，說明跟這杯的關聯

---

## 照片

![[Obsidian/調酒學習/照片/<檔名>.jpg|500]]
```

- 沒有照片時，省略整個「## 照片」段落，不要留空段落
- 材料份量若不確定精確 ml 數，用「適量」即可，不要編造精確數字
- 手法/裝飾若是推測（不是使用者明確說的），要標註「（推測）」
- **延伸探索只能推薦「尚未喝過」的調酒**：新增/修改任何一篇筆記的延伸探索前，先對照 `品飲記錄/` 底下所有檔名（這是唯一完整的「喝過清單」），確認推薦目標不在裡面。喝過的酒拿來對照分析可以寫在「個人筆記」，但不能放在「延伸探索」的推薦列表——推薦已喝過的等於沒推薦，失去擴展範圍的意義
- 新增一篇品飲記錄後，**回頭檢查既有筆記的延伸探索是否推薦到這杯新酒**，如果有要一併換掉（例如新增 Margarita 後，原本推薦「喝 Margarita」的 Sidecar/Daiquiri 延伸探索都要更新）

---

## 照片存放規則

- 統一放在 `調酒學習/照片/`，檔名用**小寫英文+連字號**，對應該杯的英文檔名
  - 例：`Berlin Stationmaster.md` → `照片/berlin-stationmaster.jpg`
- 使用者若透過聊天貼圖傳照片，Claude 無法直接存檔，需請使用者另存到本機資料夾（如 Desktop）後告知路徑，再由 Claude 讀取搬運
- 多張照片對應多杯酒時，**數量對不上或無法從描述高度確信對應關係時，必須先跟使用者確認**，不可憑空配對——錯配的照片很難被日後發現

## 歸類規則：怎麼決定 `分類` 欄位

1. 先檢查 `18杯地圖.md` 主表格，該基酒 × 該結構的欄位**指定的是哪一支經典調酒**
2. 若這杯剛好就是該欄位指定的調酒（同名或公認同一杯）→ **歸入主表**，打勾 ✅，並更新「總進度 X/18」
3. 若是變體版本（例如薰衣草曼哈頓 = Manhattan 變體）→ 主表打 `✅*`，並在圖底加註說明
4. 若基酒/結構相符但不是主表指定的那杯經典酒 → 看該格是否已被填滿：
   - **已填滿** → `分類: 同格變體`（例：Whiskey×Sour 已由 Whiskey Sour 完成，Penicillin 即為同格變體）
   - **仍空著** → `分類: 框架外`，並在框架外酒單註明它對應哪個還沒定案的格子（例：Cuba Libre 對應仍空的 Dark & Stormy）
5. 完全不在 18 杯框架內（跨基酒調配、酒吧自創等）→ 進 [[Obsidian/調酒學習/18杯地圖－框架外酒單|18杯地圖－框架外酒單]]，依「跨基酒混調」或「家族延伸」分類

---

## 廣度層 vs 深度層：格子喝到第 2 種配方時要做什麼

`18杯地圖.md` 是廣度層（格子有沒有喝過），[[Obsidian/調酒學習/18杯地圖－同格深度比較|18杯地圖－同格深度比較]] 是深度層（同格多配方的差異比較）。**新增品飲記錄若落在一個已經 ✅ 的格子**（即規則 4 的情況），除了照常規建檔外，還要：

1. 檢查 `18杯地圖－同格深度比較.md` 有沒有這個格子的段落
   - 沒有 → 新增一個段落，把「原本已完成那杯」+「新的這杯」放進比較表（甜/酸/苦/酒感/酒體/偏好 + 差異點欄）
   - 已有 → 在既有表格追加一列
2. 在 `18杯地圖.md` 主表對應格子旁加註「(N變體)」並連結到 `18杯地圖－同格深度比較.md` 該段落的錨點
3. 更新「格子深度地圖總覽」那張總表的變體數與分數範圍
4. 若新比較推翻或補強了既有結論，更新該段落的「結論」文字

**不要**把同格變體寫進框架外酒單——那份文件只放真正跳出 6×3 框架的酒（跨基酒混調、框架外家族）。

## 品完之後要同步更新的地方

每新增一杯，依 `分類` 決定要動哪些檔案：

**一律要更新 `18杯地圖.md`：**
- [ ] 「總進度 X/18」與「另有 Y 杯同格變體 + Z 杯框架外」數字
- [ ] 🧠 口味傾向歸納：若這杯的偏好分數改變了排名前段/後段的結論，重寫歸納段落
- [ ] 📅 下一杯建議：若原本建議的酒已被喝過，換成下一個未完成品項

**`分類: 18杯` 額外要做：**
- [ ] 主表格對應格子打勾 ✅（變體形式完成則打 `✅*` 並在表格下方加註）
- [ ] 📖 18杯清單表新增一列

**`分類: 同格變體` 額外要做：**
- [ ] `18杯地圖－同格深度比較.md` 新增/追加該格比較表與結論（做法見上一節）
- [ ] 主表格該格旁的「(N變體)」數字 +1
- [ ] 「18杯以外的紀錄」索引的同格變體杯數 +1

**`分類: 框架外` 額外要做：**
- [ ] `18杯地圖－框架外酒單.md` 加進「跨基酒混調」或「家族延伸」表
- [ ] 「18杯以外的紀錄」索引的框架外杯數 +1

**所有分類都要做的最後一步：**
- [ ] 回頭檢查既有筆記的延伸探索有沒有推薦到這杯新酒，有的話換掉
- [ ] 更新 `18杯地圖.md` 的「🍸 下次點酒看這裡」：若這杯就在清單上，把它移除並遞補新的一杯

## 推薦分層原則：只有一個地方是「行動清單」

系統裡有 4 個地方會出現「建議去喝什麼」，**只有第 1 個是行動清單，其他 3 個是素材庫**。這個分層要維持住，否則會退回「到處都是推薦、不知道該看哪」的狀態。

| 位置 | 身份 | 回答什麼問題 | 什麼時候看 |
|------|------|------------|----------|
| `18杯地圖.md` › 🍸 下次點酒看這裡 | **✅ 唯一行動清單** | 下一杯點什麼 | 站在吧台前 |
| 各篇品飲記錄 › 延伸探索 | 素材 | 喝過這杯後，鄰近的還有什麼 | 回顧某一杯時 |
| `18杯地圖－同格深度比較.md` › 下一步驗證 | 素材 | 想拆解某個變數，該喝哪杯 | 做變數分析時 |
| `18杯地圖－框架外酒單.md` › 擴展策略／新方向 | 素材 | 這一季該往哪個酒種開疆闢土 | 季度規劃時 |

- 三個素材庫的段落開頭都必須有 📌 導流註記，指回唯一行動清單
- 行動清單維持 **5–8 杯**，太長就失去「決策」功能；素材庫可以無限長
- 行動清單的每一列都要寫「為什麼是它」，理由要能追溯到實際分數或筆記內容，不能只寫「經典必喝」

## 不做的事

- 不自行幫使用者美化品飲心得為專業品酒詞彙，保留原始感受描述
- 不在沒有把握時幫照片配對調酒，寧可停下來問
- 不編造精確酒譜比例（ml 數），除非是查得到的經典酒譜標準比例，且要註明是「標準比例」而非使用者實測
