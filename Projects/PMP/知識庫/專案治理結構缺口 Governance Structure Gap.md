# 專案治理結構缺口 Governance Structure Gap

> [[Projects/PMP/知識庫/_索引|← 知識庫索引]] ｜ `Governance 績效領域` › `Monitoring and Controlling` › `Monitor and Control Project Performance`

> [!tip] 一句話核心
> **「不同關係人群體系統性意見不合、決策一再卡住」不是一次性的人際衝突，是治理架構裡「誰有最終決策權」這件事沒講清楚。衝突處理技巧是對個人/團隊的戰術，治理結構是對整個決策機制的架構問題——層級不同。**

---

## 案例核心（E064）

專案經理觀察到專案落後進度，原因是**組織高層管理**與**外部關係人**之間的**意見衝突**，導致關鍵決策一再延遲。題目問：PM 應該怎麼做？

| 選項                                | 為什麼錯／對                                                                                                  |
| --------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **檢視專案治理的充分性，並確保有適當的架構**（正解）      | ✅ 問題的本質是**決策權責沒有清楚界定**——兩個關係人群體各有立場，卻沒有機制能把分歧收斂成一個決策。這是**治理層級**的缺口，必須先把「誰在什麼情況下有最終決定權」的架構補上，否則同類延遲會不斷重演 |
| 檢視剩餘範圍並重新設定時程基數，以因應決策延遲（你選的，常見誤選） | ❌ **治標不治本**——重新設定時程只是承認延遲已發生、幫既成事實找一個新基準，不處理「為什麼會一再延遲」這個根因，下一次同樣的意見分歧出現時，時程還是會繼續跑掉                      |
| 將專案團隊與高層管理及利害關係人等外部因素隔離           | ❌ **迴避而非解決**——隔離團隊只是把分歧暫時擋在門外，決策權責不清的根本問題仍在，而且高層與外部關係人本來就是必要的決策輸入來源，隔離反而切斷了讓決策發生的管道                     |
| 審查利害關係人登記冊，並確保溝通符合溝通管理計畫          | ❌ **假設錯了問題類型**——題目描述的不是「資訊沒傳到」（溝通執行面的問題），而是**決策本身卡住**，雙方立場都清楚、但沒有機制把分歧收斂成決定。溝通計畫做得再確實，也解決不了「誰拍板」這件事沒被定義 |

> 🔑 判準口訣：題目出現「**不同關係人群體**（如高層 vs 外部關係人）**系統性**意見不合、**關鍵決策一再延遲**」這組訊號 → 先問**治理架構裡有沒有定義清楚「誰在這種情況下有最終決策權」**，而不是急著處理表面的衝突或時程。

## 跟「衝突處理與升級階梯」的分界

這題最容易跟 [[Projects/PMP/知識庫/衝突處理與升級階梯|衝突處理與升級階梯]]（Resources › Executing › Lead the Team）搞混，兩者看起來都在處理「意見不合」，但層級完全不同：

| | 衝突處理與升級階梯 | 治理結構缺口（本題） |
|---|---|---|
| **問題主體** | 團隊內部、特定個人或小群體 | **組織層級**的關係人群體（高層、外部關係人） |
| **本質** | 一次性的人際摩擦，靠**技巧**化解（協作、妥協…） | **系統性、重複發生**的決策卡關，靠**架構**補洞 |
| **解法方向** | PM 先私下談，談不攏才往上升級 | 檢視**決策權責／治理架構**本身夠不夠清楚 |
| **錯誤示警** | 跳過本人直接找主管＝越級 | 把人隔離開＝迴避，不是解決 |

> 🔑 判準：看到「**團隊裡**某人／某小組」的摩擦 → 衝突處理技巧＋升級階梯。
> 看到「**組織層級**的關係人群體**反覆**卡住關鍵決策」→ 先檢視**治理架構**（決策權責是否清楚界定），這是結構問題，不是人際技巧能解的。
