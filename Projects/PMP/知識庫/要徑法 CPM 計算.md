# 要徑法 CPM 計算

> [[Projects/PMP/知識庫/_索引|← 知識庫索引]] ｜ `Schedule 績效領域` › `Planning` › `Develop Schedule`

> [!tip] 一句話核心
> **把每條「從頭走到尾」的完整路徑都加總一遍，最長的那條才是要徑——半路停在中間節點不算一條路徑。**

![[要徑計算範例.svg]]

---

## 計算步驟

```
① 列出網路圖裡所有「從開始走到結束」的完整路徑
② 把每條路徑上每個活動的歷時加總
③ 加總數字最大的那條 = 要徑（Critical Path）
④ 要徑總長 = 專案最短工期
⑤ 其他路徑的浮時 Float = 要徑長度 − 該路徑長度
```

要徑上所有活動的浮時 = 0（不能延誤，一延誤整個專案就延誤）。
非要徑活動有浮時，代表有彈性、可以晚一點做而不影響專案完工日。

---

## ⚠️ 最常見的算錯方式：路徑沒走完就停了

範例網路圖裡：Start → A → C → E → Finish、Start → B → D → E → Finish、Start → B → D → F → Finish 三條路徑都存在。

- Path A-C-E：8+1+7 = 16 天
- Path B-D-E：7+6+7 = **20 天 ← 要徑**
- Path B-D-F：7+6+2 = 15 天

**常見誤選 Path B-D-F（15 天）**：只看到 B→D 之後接了 F，就把這條路徑當終點，忘了 D 同時也連到 E，而 **B-D-E 才是真正走到底、加總最大的那條**。判斷要徑前一定要先確認「這條路徑真的從 Start 走到 Finish 了嗎」，不要在中間節點就停下來比大小。

---

## 判斷口訣

> **先窮舉路徑，再加總比大小，最後才看哪條是要徑。**
> 順序反了（沒列完路徑就直接挑一條算）是最容易錯的地方。
