# 滾動式規劃 Rolling Wave Planning

> [[Projects/PMP/知識庫/_索引|← 知識庫索引]] ｜ `Governance 績效領域` › `Planning` › `Integrate and Align Project Plans`

> [!tip] 一句話核心
> **Rolling Wave 是「規劃的顆粒度」隨時間展開；不是開發方法，不是生命週期，不是敏捷儀式——它可以套在 Predictive 專案上，也可以套在 Agile 專案上。**

---

## 這題容易混淆的四個名詞

| | **Rolling Wave Planning<br>滾動式規劃** | **Iterative Development<br>疊代式開發** | **Adaptive Lifecycle<br>自適應生命週期** | **Agile Sprint Planning<br>敏捷迭代規劃** |
|---|---|---|---|---|
| **本質** | **規劃技術**（漸進明細化 progressive elaboration） | **開發方法**（反覆修正同一個成果） | **生命週期類型**（整個專案採用敏捷／自適應的方式運作） | **敏捷儀式**（sprint 開始前排定這個 sprint 要做什麼） |
| **在回答什麼** | 「近期怎麼規劃、遠期怎麼規劃」 | 「東西怎麼被做出來」（做→回饋→改→再做） | 「整個專案的運作模式是什麼」 | 「這個 sprint 具體要做哪些項目」 |
| **關鍵特徵** | **近期詳細規劃、遠期高層級規劃**，隨時間推進逐波展開細節 | 反覆修正**同一個**產出直到對，不強調「近期細/遠期粗」的規劃節奏 | 整個生命週期都是短週期、持續交付、擁抱變更——範圍比 Rolling Wave 大很多 | 只發生在敏捷框架**內部**的一個活動，範圍比 Rolling Wave 窄很多 |
| **適用範圍** | Predictive、Hybrid、Agile 都能用——是**規劃節奏**，不綁定方法論 | 通常伴隨 Predictive 或 Hybrid 中的原型／反覆修正場景 | 只用於整個專案本身就是敏捷／自適應運作時 | 只在敏捷專案的 sprint 循環中出現 |

---

## 🎯 判準口訣

> 題目講的是「**近期做詳細計畫，遠期先做高層級計畫，等資訊明朗再細化**」→ **Rolling Wave Planning**，這是漸進明細化的規劃技術，跟專案整體是不是敏捷無關。
>
> 只有題目明確出現 **backlog、PO、sprint、擁抱變更貫穿全專案**，才是 Agile / Adaptive Lifecycle。
> 只有題目強調「反覆修正**同一個東西**直到滿意」，沒有「近期細、遠期粗」的規劃節奏，才是 Iterative Development。

---

## ⚠️ 本題錯誤示範

題目：藥廠研究專案，前期基礎研究要先做，後期測試方案與法規要求要等前期結果出來才能確定。PM 計畫「**現在把近期工作規劃詳細，之後隨著資訊明朗再詳細規劃後續階段**」。

錯選 **Iterative Development（疊代式開發）**：疊代式開發講的是「反覆修正同一個交付物」，題目裡沒有「做出來、拿去驗證、改、再做」的循環——題目講的是**規劃本身的顆粒度隨時間展開**，這正是 Rolling Wave Planning 的定義,不是開發方法。

**正解：Rolling Wave Planning**——近期詳細規劃、遠期高層級規劃，等資訊明朗後再逐波細化。
