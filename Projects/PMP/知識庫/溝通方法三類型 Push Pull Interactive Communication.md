# 溝通方法三類型：Push／Pull／Interactive Communication

> [[Projects/PMP/知識庫/_索引|← 知識庫索引]] ｜ `Stakeholders 績效領域` › `Planning` › `Plan Communications Management`
> 相關知識點：[[Projects/PMP/知識庫/溝通管理三流程辨析|溝通管理三流程辨析]]（那則講**流程**歸屬，這則講**方法**選擇）

> [!tip] 一句話核心
> **資訊複雜、容易被誤解、牽涉多方時，選「雙向即時」的 Interactive；資訊單純、只是通知、不需要立刻確認的，才用 Push／Pull。誤解已經發生、造成延誤成本時，答案幾乎都是 Interactive。**

---

## 三種溝通方法

| 方法                                | 方向                        | 典型形式                           | 適合情境                                          |
| --------------------------------- | ------------------------- | ------------------------------ | --------------------------------------------- |
| **Push Communication 推播式**        | **單向**，發送方主動送出，不保證對方收到、看懂 | Email、報告、公告、**儀表板（dashboard）** | 單純通知、資訊量不大、不需要立即釐清                            |
| **Pull Communication 拉取式**        | **單向**，接收方自己去取用，發送方不主動推送  | 內部網站、知識庫、共享資料夾                 | 大量資訊、接收方可自行決定何時查閱                             |
| **Interactive Communication 互動式** | **雙向、即時**，雙方可以來回交換、當場澄清   | **會議（含視訊）**、電話、即時通訊            | **資訊複雜、容易被誤解、牽涉多方協調**——需要當場確認「我懂的跟你講的是不是同一件事」 |

> 🔑 判準不是「這個工具先不先進」，而是「**有沒有雙向、即時的回饋機制**」。儀表板再即時、再集中，本質上還是**單向推播**——接收者看到資訊，但沒有管道在當下跟對方確認理解是否一致。

## 案例核心（E077）

大型施工專案，**多家分包商＋多元團隊**，近期發生**多起溝通不良事件**，導致延誤與成本增加。題目問：PM 該怎麼做改善協調、減少誤解？

| 選項                                     | 為什麼錯／對                                                                                                                                              |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| **引入強制性的每週協調會議，與所有分包商及關鍵團隊成員**（正解）     | ✅ 這是**Interactive Communication**——會議讓多方**同時在場、即時來回確認**，能在當下就把「誤解」攔下來，而不是等誤解造成延誤後才發現。題目的核心訊號是**「誤解已經造成實際延誤與成本」**，代表現有方式**沒有即時澄清的機制**，需要補的正是雙向、同步的管道 |
| 建立集中式、即時溝通儀表板，讓所有相關方同時掌握最新狀況（你選的，常見誤選） | ❌ **還是 Push／Pull Communication**——儀表板再即時，本質上仍是**單向**：資訊被放上去，但**沒有機制確認每個人看懂了、理解一致**。多家分包商、多元背景的情境下，光是「看到同一份資訊」不代表「解讀一致」，這正是題目描述的「**誤解**」會持續發生的原因     |
| 執行一項政策，要求所有溝通必須由指定的專案溝通官完成             | ❌ **製造新的單點瓶頸**——所有訊息要先經過一個人轉手，不但**拖慢**溝通速度（跟題目要解決的「延誤」方向相反），而且轉手過程本身就可能**產生新的誤解**（轉述失真）                                                             |
| 建立詳細的溝通流程圖，明確說明資訊分享的管道與規範              | ❌ **這是在補 Plan 階段的文件**（規則說明），題目描述的是**溝通已經在執行、且持續出錯**——補一份流程圖只是把規則寫得更清楚，不會讓多方在當下**即時核對理解**，治標不治本                                                      |

> 🔑 判準：題目出現「**多方／跨組織協調**」＋「**已經發生誤解、造成實際損失（延誤、成本）**」這組訊號 → 優先選 **Interactive Communication**（會議、即時雙向交流），不要被「更即時的工具」（儀表板）、「集中窗口」（溝通官）、「更清楚的文件」（流程圖）這些**看似更有條理**，但本質仍是單向或靜態的選項帶走。

## 跟「溝通管理三流程辨析」的分工

| | 溝通管理三流程辨析 | 本篇：溝通方法三類型 |
|---|---|---|
| 回答的問題 | 現在是 Plan／Manage／Monitor **哪個流程** | 該用 **Push／Pull／Interactive 哪種方法** |
| 判準依據 | 看**動詞**（決定規則 vs 照做 vs 檢查成效） | 看**資訊複雜度與誤解風險** |

兩者常常一起出現：選完流程（通常是 Manage／Plan Communications），接著題目再追問「具體該用哪種方法」，就要切到這篇的判準。
