### 自動化系統（4 支腳本 + cron）
**做了什麼：**
- `notify.py`（08:00）：抓 RSS → Claude 篩選新聞 → 產出今日代辦
- `quest.py`（07:55）：讀昨日 checkbox → 計算積分 → 更新 progress.json
- `book_fill.py`（08:05 週一）：推薦本週書摘 + 小說任務，寫入 `Skills/book-fill/本週任務.md`
- `daily_note.py`（23:00）：產出 Claude 工作紀錄快照 + 書籍狀態同步

**推論：**
手動每天做這些事太繁瑣，且容易忘記。自動化的目的是讓「保持習慣的門檻降到最低」——任務清單早上自動出現，積分不需要手算。

---

### 修煉積分系統（quest-system）
**做了什麼：**
- PRD 定案：純加分制 + 連擊機制
- 獎勵：700 pt 衣著採購 / 1,500 pt 兩天一夜旅行
- 里程碑額外加分（系統上線 +200、PMP 書讀完 +300 等）

**推論：**
Wilson 的問題是分析 > 行動，習慣容易斷。遊戲化進度條的目的是讓「做了什麼」有視覺回饋，獎勵刻意排除食物（減肥目標），用旅行等大額體驗當誘因，維持動力持續性。

---

### Skills 架構（資料夾 + README）
**做了什麼：**
- 所有 skill 從單一 .md 改為 `Skills/xxx/README.md` + 腳本同層結構
- 調用鏈確立：`CLAUDE.md → Skills/instructions.md → 各 skill/README.md`
- 新增 save-to-obsidian、quest-system、book-fill、daily-note 四個 skill

**推論：**
原本 skill 只有說明文件沒有腳本，或腳本和說明分兩個地方，我（Claude）每次要靠記憶找位置。統一成資料夾結構後，README 在哪腳本就在哪，維護成本低，新增 skill 也有清楚規範可循。

## 🔄 調整

### notify.py 新聞架構升級
**改了什麼：**
- 單篇抓取 → 每 category 抓多則候選，交由 Claude 依條件篩選

**推論：**
原本直接抓第一則新聞，品質不穩定，容易抓到娛樂或不重要的內容。改成候選制後，Claude 有選擇空間，可以依篩選條件（國際影響力、政府政策、產業動態）挑最相關的。

---

### book_fill.py 執行時機：每日 → 每週一
**改了什麼：**
- cron 從 `5 8 * * *` 改為 `5 8 * * 1`
- 輸出從直接附加今日代辦 → 寫入 `Skills/book-fill/本週任務.md`，notify.py 每天讀取

**推論：**
書摘任務每天出現會造成壓力感，且每天覆蓋代辦會讓週二之後看不到任務。改成週一產出、每天帶入，視覺上是本週目標而非每日強制，壓力降低，任務不會消失。

---

### CLAUDE.md 精簡
**改了什麼：**
- 移除自動化系統細節說明（下放至各 skill README）
- 補上閉環原則（每次改動必須同步更新 CLAUDE.md）
- 補上 Wilson 思維模型（分析 > 行動的風險）

**推論：**
CLAUDE.md 越長，每次對話載入的噪音越多。把技術細節下放到 skill README，CLAUDE.md 只留「我是誰、結構是什麼、行為準則」，讓我每次讀它時能快速定位，而不是在一大堆設定裡找方向。

**刪了什麼：** `daily-note.md`、`save-to-obsidian.md`、`sync-book-status.md`（根目錄散落的 .md）

**刪了什麼：** `Skills/sync-book-status/` 資料夾

**推論：** 書籍狀態同步邏輯很輕量，沒有理由單獨一個 skill。直接合併進 `daily_note.py`，每天 23:00 一起執行，減少系統複雜度。
