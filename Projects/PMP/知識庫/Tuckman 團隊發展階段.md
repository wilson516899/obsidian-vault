# Tuckman 團隊發展階段

> [[Projects/PMP/知識庫/_索引|← 知識庫索引]] ｜ `Resources 績效領域` › `Executing` › `Lead the Team`

> [!tip] 一句話核心
> **Tuckman 量的是「團隊互動型態」，不是「個人產出」。**

---

## 五階段

```
Forming → Storming → Norming → Performing → Adjourning
 形成      風暴       規範        表現         解散
```

| 階段                | 團隊狀態      | 辨識關鍵字                   |
| ----------------- | --------- | ----------------------- |
| **Forming** 形成    | 剛認識、客氣、觀望 | 依賴 PM 給方向、角色不清、**尚無衝突** |
| **Storming** 風暴   | 衝突浮現      | 打斷、否定、爭主導權、抗拒協作、有人退縮沉默  |
| **Norming** 規範    | 建立共識      | 開始互信、訂出工作方式、衝突能自行處理     |
| **Performing** 表現 | 自組織       | **相互依賴**、高效交付、PM 可退居支援  |
| **Adjourning** 解散 | 收尾        | 釋出資源、經驗總結、慶祝            |

---

## PM 在各階段的角色（考點）

| 階段           | 領導風格               | 該做什麼           |
| ------------ | ------------------ | -------------- |
| Forming      | **指導型** Directing  | 給方向、訂目標、建立團隊章程 |
| **Storming** | **教練型** Coaching   | 引導衝突浮上檯面並處理    |
| Norming      | **支持型** Supporting | 促進協作、鞏固規範      |
| Performing   | **授權型** Delegating | 退居支援，別擋路       |

---

## ⚠️ 常見陷阱

| 陷阱                                | 破解                                            |
| --------------------------------- | --------------------------------------------- |
| 看到「某人表現優異／高品質產出」就選 **Performing** | 那是**個人**績效。Performing 的定義是**團隊相互依賴**地交付       |
| 團隊在碎裂、各自為政 → 誤判為 Performing       | 方向剛好相反，碎裂是 **Storming**                       |
| 以為「沒人吵架」就是 Norming                | 也可能是 Forming（還在客氣）或 Storming 後期的**壓抑**（有人被消音） |
| 以為階段只能前進                          | **會倒退**。換成員、換範疇、換 PM 都可能打回 Forming/Storming   |

> 💡 一個強力的個人貢獻者，常常是 Storming 的**成因**，不是 Performing 的證據。

---

## 判斷口訣

> **看到「誰厲害」不要選 Performing；看到「大家在吵或在躲」就是 Storming。**
> 看**關係**，不看**績效**。

---

## 🎯 情境應用：跨部門、從未合作過的團隊，專案初期就出現緊張與合作不良，該怎麼介入

E076：新專案團隊由**來自不同部門、從未合作過**的員工組成，**專案初期**就出現明顯**緊張與合作不良**。題目問：PM 該怎麼做來提升團隊合作？

| 選項 | 為什麼錯／對 |
|---|---|
| **組織以協作與溝通為重點的團隊建立活動**（正解） | ✅ 這個團隊的核心缺口是**彼此不熟悉、沒有共同合作經驗**——團隊建立活動直接針對這個缺口設計，用結構化的方式讓**陌生人建立信任與默契**，幫團隊從 Forming／Storming 往 Norming 推進。題目描述的「緊張、合作不良」是**關係層面**的症狀，團隊建立活動是對症的介入 |
| 在專案計畫中明確指派每位團隊成員的角色與責任（你選的，常見誤選） | ❌ **方向是對的基本功，但沒對到題目描述的症狀**——角色釐清處理的是「**不知道自己該做什麼**」這種**結構性模糊**，但題目講的是「**緊張、合作不良**」這種**人際關係**層面的問題。角色定義清楚，不代表互不認識的人就會自然合作順暢 |
| 實施衝突解決程序，以迅速處理並解決爭議 | ❌ **這是事後處理機制，不是建立合作的介入**——衝突解決程序是等**具體爭議**發生後拿出來用的工具，題目目前描述的是普遍性的「緊張與合作不良」，還沒到需要正式仲裁爭議的程度，而且這個工具**不會主動建立**團隊之間的信任與協作默契 |
| 安排定期績效評估，以監控個人對團隊的貢獻 | ❌ **量的是個人產出，不是團隊互動**——呼應本篇一開頭的一句話核心：Tuckman 量的是團隊互動型態，不是個人產出。績效評估是**個人層級**的工具，在團隊關係都還沒理順的階段用它，只會讓大家更關注「自己的考績」而非「彼此合作」，甚至可能加劇緊張 |

> 🔑 判準：團隊是**跨部門、彼此陌生、剛組成**，症狀是**緊張、合作不良**（關係層面）而不是「不知道該做什麼」（結構層面）時 → 優先選**直接建立關係與信任**的介入（團隊建立活動），而不是角色釐清（治結構，不治關係）、衝突程序（治已發生的爭議，不治普遍緊張）、或績效評估（量個人，不量團隊）。
